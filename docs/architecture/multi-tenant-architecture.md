# Multi-Tenant Architecture

## Tenant 与业务边界

Tenant 是企业使用平台业务资源的组织边界。多个企业共享产品与 CloudBase 业务环境，但各自的业务数据、知识资源访问及 AI 配置受到租户边界约束。

`tenant_id` 是已确认的业务数据隔离维度。共享环境不代表租户可以相互访问数据；服务端权限校验需要结合当前身份、租户状态和目标资源所属租户，而不能仅依据客户端传入的租户标识作出授权。

## 身份与成员关系

微信用户身份回答“谁在请求”，租户成员关系回答“该用户以哪个企业成员身份访问业务”。身份解析、Tenant 状态检查与权限校验共同约束访问范围，用户身份本身不能替代租户访问授权。

Platform Admin 使用独立管理员认证，包括 SQLite、Argon2id、TOTP MFA 和 Session 管理。管理员身份与微信用户身份分别处理，不推定其账号、成员关系或权限模型相同。

成员关系的存储结构、角色划分及具体授权规则，具体实现细节未在当前 Showcase 仓库核验。

## 租户级 AI 配置与资源隔离

- **业务数据与文件**：数据查询和素材访问应受租户及权限边界约束，不能因位于同一 CloudBase 环境而跨租户读取。
- **企业知识与 AI 配置**：租户级 AI 配置支持企业使用各自的知识与 AI 能力配置；配置选择与资源访问同样需要服务端校验。
- **内容与统计**：内部内容操作遵循业务授权；发布与公开读取具有不同权限边界，公开页面的存在不意味着内部数据整体开放。

上述隔离原则不等同于“每租户独立数据库、独立 Dify 实例或独立模型部署”。资源映射、数据库查询约束及底层权限实现，具体实现细节未在当前 Showcase 仓库核验。
