# Data Flow & Security Boundaries

## 请求入口与可信身份

小程序请求进入 CloudBase 云函数后，服务端采用 `cloud.getWXContext().OPENID` 作为微信身份的可信来源，解析身份并结合租户成员关系、Tenant 状态及权限检查决定访问范围。客户端提交的身份、租户标识或资源标识不能单独构成授权依据。

Platform Admin 的请求由 Next.js Server / API Routes 承接，管理员认证使用独立 SQLite 存储及 Session 管理，并包含 Argon2id 与 TOTP MFA。该认证边界独立于微信身份，不将小程序的 OPENID 流程套用于管理端。

两个入口接入同一 CloudBase 业务环境；`tenant_id` 是业务数据隔离维度。服务端的数据与资源访问应符合当前身份的租户权限范围。

## AI Generation 的服务端控制

已确认公开内容生成包含服务端生成控制、quota 管理、`requestId` 幂等、Original / Current 双模型及内容持久化。以下按责任说明控制原则，不表示所有 AI 功能具有完全相同的执行顺序：

| 环节 | 服务端责任边界 |
| --- | --- |
| 权限与配置 | 结合身份、租户状态与权限决定能否生成，并约束租户级 AI 配置的使用。 |
| quota 与幂等 | 服务端管理生成额度，以 `requestId` 处理重复生成请求。具体扣减、回退和并发策略不作推定。 |
| 素材读取 | 按具体功能读取所需素材时，应校验素材归属与读取权限；不假设每次生成都读取企业知识或调用 RAG。 |
| AI 调用 | 在已授权的业务上下文中集成 Dify / 模型能力，不由客户端决定可信身份或最终授权。 |
| 输出校验 | 保存前应按业务要求检查输出是否满足可用条件；具体字段、校验规则及失败处置未在此确认为已实现机制。 |
| 结果保存 | 已确认内容持久化及 Original / Current 双模型；保存结果应遵守租户和资源权限边界。 |

素材选择、输出校验、调用顺序与事务边界，具体实现细节未在当前 Showcase 仓库核验。

## 不同业务流程的权限边界

- **知识问答**：Dify 知识库链路提供检索及知识来源引用，不能据此推定与公开内容生成共用同一调用流程。
- **文件处理**：跟踪上传、异步处理和 Dify 同步的任务状态，涉及失败识别与恢复；它与生成请求幂等是独立机制。
- **内容发布与公开访问**：发布授权和公开读取分别控制内容操作与对外访问。匿名事件回流支持 PV / UV 及分享统计，不推定具体分享回调实现。

## 客户端与服务端分工

客户端负责界面交互、提交业务输入与展示结果。服务端负责可信身份解析、租户和权限校验、业务资源访问及生成控制；客户端展示的权限或剩余额度不能替代服务端判断。
